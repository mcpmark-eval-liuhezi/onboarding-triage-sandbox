# Code Review Checklist

Use this checklist when reviewing a pull request. Placeholder content for the drill.

## Description

- [ ] The pull request describes what changed and why.
- [ ] The pull request references a tracking issue, where one exists.

## Code

- [ ] The changes are covered by tests, or a reason is given why not.
- [ ] Naming and style match the project conventions.
- [ ] No obvious debugging code or commented-out blocks are left behind.

## Process

- [ ] The branch is up to date with the base branch before merging.
- [ ] Any open questions are captured as comments on the pull request.
